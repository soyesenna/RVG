# 보장과 교환 — RVG 0.1.0.dev53

이 문서는 RVG가 무엇을 지키고, 그 대가로 무엇을 내주는지 적는다. 기준은 0.1.0.dev53이다. 코드는 0.1.0.dev46과 같고(결정 경로는 dev44와 같다), 정책은 sha256 `24777fc8…`다. dev47에서 부모 EVID-1(2026-10-22)의 측정으로 같은 날 지연 배수, 판독을 맞춘 오류율, 현행 판의 장문 값을 채웠다. dev53에서는 부모 EVID-2(2026-10-23)의 같은 커버리지 선택적 기준선 결과로, 순수 RAG와의 정확성 비교에 정정 주석을 붙였다(코드·정책은 dev47과 같다). 같은 dev53 문서 판의 둘째 커밋에서 부모 EVID-3·3b·4·5·5b(2026-10-23)로 정정 주석을 더했다(코드·정책 그대로).

이 파일은 한국어 원본이다. 정본은 영어판 [GUARANTEES.md](GUARANTEES.md)이고, 두 판의 수치는 같다(`scripts/check_doc_numbers.py`).

**읽는 법.**
- **두 종류의 문장이 있다.**
  - **구조적 보장**(§1)은 코드가 그렇게 동작하도록 만든 성질이고, 시험이 지킨다.
  - **측정된 성질**(§2·§3)은 특정 자료 풀과 모델 조합에서 잰 값이다. 다른 KB·질문·모델에서 같은 값이 나온다는 인증이 아니다.
- **수치에는 실험 ID와 날짜를 붙였다.** 실험 보고서는 연구 저장소(부모)의 `docs/…`에 있다. 분모·구간·채점기·run을 적은 근거 표는 부모 `docs/RVG_PRODUCT_CONTRACT.md`다. 이 문서는 기존 보고서의 수치만 옮기고 새로 재지 않았다.
- **비교 기준은 같은 모델의 순수 RAG**다. Claude Haiku가 검색 상위 10개(BH10) 또는 3개(BH3)를 보고 바로 답하고, 통제기는 없다. RVG는 같은 Haiku를 작성기로 쓰고, 통제기(Jev 판정)가 확인한 부분만 공개한다.
- **측정한 모델 조합.** 작성기·추출기는 구독 Claude Code CLI `claude-haiku-5-5`, 판정은 OpenRouter Jev `typesafe/jev-1.14`, 임베딩은 OpenRouter Gemini다. 모델을 바꾸면 §2·§3을 다시 재야 한다.

> **정정(D-DIM-DECL, 0.1.0.dev56, 부모 PROD-1, 2026-10-24).** 기존 문장은 그대로 두고 덧붙인다.

> **추가(0.1.0, 2026-10-27) — 플랫폼과 무관한 순위.** dense 검색은 BLAS로 훑은 뒤, top-k에 들 수 있는 행(k번째 훑기 점수에서 증명된 오차 한계의 두 배 안)만 BLAS 없이 고정 순서로 다시 계산해 순위와 점수를 정한다. 이 고정 순서는 곱을 하나씩 반올림한 뒤 numpy pairwise 합으로 더하는 것이고, 질의 정규화도 같은 순서다. 같은 저장 벡터와 같은 질의면 어느 CPU·BLAS에서나 순위와 점수가 비트까지 같다. 동점은 catalog 순서(`(id, revision)` 오름차순)다. 전에는 BLAS 점수로 바로 순위를 매겨, 기계가 다르면 마지막 비트와 근소 차 행의 순서가 달라질 수 있었다. 이 문서의 측정값은 바뀌지 않는다. 점수는 마지막 몇 자리만 다르고, N0 재생 관문과 EVID-4 감사는 이전과 같다(CHANGELOG 0.1.0).

## 1. 구조적 보장(코드와 시험)

1. **확인한 것만 공개한다.** 답은 허가되고 그 시점에 유효한 KB 문서만을 근거로 쓴다. 통제기가 근거로 확인한 부분만 `FULL`·`PARTIAL`로 공개한다. 나머지는 `ABSTAIN`(또는 `UNRESOLVED_SCOPE`·`ERROR`)이다. 확인하지 못한 문장을 내보내는 경로는 없다.
   - **공개하지 않은 결과에는 초안 값이 없다(0.1.0, 부모 PUB-2).** 통제기가 보류한 초안의 짧은 답, 주장 문장(`assessment`·`assessment_before_recovery`의 `claims`), 짝 초안의 짧은 답(`trace.consistency`), 본문·문장을 공개 표면(`UniversalEngine.answer`, `session.answer` 봉투, CLI)에서 지운다. 초안은 opt-in 넘김 패킷(`result.handoff`)에만 있다. 전에는 보류 결과의 `short_answer`에 확인 안 된 초안 값이 남았다(공개 전 개발자 시험). 평가 기록(`rvg.testing.records.answer_one`)은 지운 값을 결과 밖 `held_draft`에 둔다.
2. **하나의 정책.** 모든 KB·언어가 정책 파일 하나(`rvg/resources/policies/universal.json`)를 쓴다. KB·언어별 profile, threshold, 검색 구성, top-k, 사람 보정은 없다. 모든 답에 정책 hash(`config_hash`)가 찍힌다.
3. **공개 직전 회수·권한 확인.** 모든 공개 모드에서 공개 직전에 회수 여부와 principal의 권한을 다시 확인한다(`release_authorize`).
4. **공개 확인(scoped, dev27부터 기본)의 보장 범위는 `authority + watermark + cutoff`다.**
   - 모든 변경이 CLEAR(답이 읽은 것과 무관)로 판정되면, fence 상태(공개 확인이 읽은 지식 번호와 ACL epoch)에서 같은 principal·질문·선택으로 새로 돌렸을 때 모든 검색이 같은 seed와 문서를 얻는다.
   - 보장하지 않는 것: 그룹 소속 변경, 상태 저장소 밖의 변경(outbox를 거치지 않는 쓰기), 모델 출력의 재현.
   - 판정할 수 없는 변경(UNKNOWN)은 보류 쪽(전역 규칙)으로 떨어진다. 자세한 정의는 `rvg.universal.scoped` 모듈 설명에 있다.
   - 답의 검색이 벡터가 아직 없는 문서(pending)를 읽었으면, 그 문서들은 BM25로 순위가 매겨져 정확한 워터마크가 없다. 그러면 답과 무관한 변경도 UNKNOWN(`no_exact_watermark`)이 되어 보류된다. 안전 쪽 보류이고, 계속 쓰는 프로세스가 문서를 넣고 벡터를 나중에 쓰는 환경에서 나타난다(부모 PUB-2: PostgreSQL 반복 시험 10회 중 2회).
5. **기록·재생으로 결정을 재현한다.** 같은 tape(HTTP 시도 단위 녹화)를 재생하면 결정·공개 답·공개 기록이 바이트까지 같다.
   - 판마다 N0 재생 관문 두 벌(각 120요청)을 엄격 일치로 통과시킨다.
   - dev44는 dev43의 live tape 150요청을 재생해 150/150 같았다(부모 PERF-1, 2026-10-21).
   - **정정(2026-10-23, 부모 논문 근거 지도 (C)·EVID-4 표 3).** "바이트까지 같다"의 정확한 뜻은 다음과 같다.
     - 기준 재생 대비로는 결정·공개 답·공개 기록·trace가 엄격히 같다.
     - 원 기록 대비로는 감사 키 `provenance`·`tentative`를 허용 목록으로 뺀 일치다. 원 기록과 그대로 견주면 감사 키 차이로 같은 요청이 없다.
     - 모델 출력 자체의 재현은 여전히 보장 밖이다.
   - **0.1.0 결과 계약을 넘는 재생(부모 PUB-2).** 0.1.0 이전 기록은 같은 규칙(보류 결과의 초안 값 제거)을 옛 결과에 적용하는 `rvg.testing.records.contract_view`로 읽어 견주고, 지운 초안 값은 새 기록의 `held_draft`와 바이트 단위로 견준다(n0b 120/120·보류 초안 12/12, s0jev114 120/120·19/19).

- **근거(부모 EVID-4, 2026-10-23): 위 1·3·4·5를 기록으로 전수 감사했다.** 판정기 없이 코드로 확인했다.

## 5. 저장소와 운영 요구

- **기본 공개 확인(scoped)이 읽는 것.** 상태 저장소의 ACL epoch, 문서, 회수, 숨김(`hidden`), 공개 권한 확인(`authorize_release`)은 포트의 필수 기능이다. 그 밖에 다음이 필요하다.
  - **outbox**: 문서 `insert`·`revoke`·`acl`·`vector` 행과 시작 표시(`outbox_mark`). SQLite·PostgreSQL 상태 저장소가 갖췄다. 사용자 정의 저장소에는 없을 수 있다.
  - **`Release.hidden`**(U32): 공개 영수증의 fence 때 가시성이다. 주지 않으면 `acl_moves = after_check`가 `hold`와 같아진다. 확인 중 ACL이 움직이면 보류한다.
  - **정확 점수 색인**: local exact(`EXACT_CANONICAL`), pgvector·Qdrant(`EXACT_NATIVE`)가 해당한다. 근사 색인과 lexical 검색은 watermark 단계가 UNKNOWN이다.
- **빠진 기능이 있으면 안전 쪽으로 떨어진다.** 해당 변경이 UNKNOWN이 되어 보류로 떨어진다(가용성 손실, 오공개는 아님). 이런 저장소로 동시 쓰기가 많은 부하를 받으면 공개가 크게 줄 수 있다. 연구 저장소 N3L에서 `current` 모드의 공개가 거의 0이 된 것과 같은 모양이다.
- **matrix 디렉터리(파일 저장소).** 기본 layout `base_delta`는 `v3/base_delta/`에 쓴다. 새 디렉터리의 첫 검색은 전체 빌드를 한 번 한다. delta가 base의 θ(0.10)를 넘을 때마다 base를 다시 쓰므로 쓰기 증폭은 O(θN)이다. 1건/초 × 읽기 4에서 디렉터리 최대 점유는 1.015배였다(FIX-MATRIX-GEN).
- **유휴 CLI 프로세스.** 미리 띄운 프로세스가 이벤트 루프(풀)마다 최대 2개 있다. 하나에 평균 약 270 MB이고 p95는 353 MB다(PERF-1 A′, Claude Code 2.1.306).
  - 300초보다 오래된 프로세스는 다음 호출 때 거둔다. 호출이 없으면 루프가 끝날 때(`shutdown_asyncgens`)나 프로그램이 끝날 때(`atexit`)까지 남는다.
  - 결과를 돌려준 뒤 끝나는 중인 프로세스는 배경에서 거두고, 30초 안에 끝나지 않으면 죽인다. 그래서 순간 프로세스 수가 CLI 슬롯 수보다 잠깐 많을 수 있다.
- **CLI 판.** 결과 즉시 반환과 미리 띄우기는 Claude Code 2.1.306의 출력 형식(결과 JSON, stream-json 입력)에서 확인했다. 형식이 바뀌면 실패 결과처럼 오류로 드러난다(시간 초과·취소 의미는 그대로다).

  - **보장하지 않는 것.**
    - **신선 경로와의 일치.** 캐시는 원 결정을 재현한다(적중 결정의 원 결정 일치 99.5%). 그래서 같은 의미의 다른 문장에 새로 생성했을 때의 결정과는 그 경로의 변동만큼 다르다(캐시 대 신선 92.7~93.2%). 사전 규칙 ④·④′(b)는 이것을 KB별로 요구했고 미달이었다.
    - **반복 스레드가 많은 KB에서의 항목 선택.** TechQA처럼 거의 같은 질문이 여러 요청으로 있는 KB에서는 다른 요청의 항목이 골라질 수 있다(PROD-3에서 공개↔보류가 바뀐 2건이 모두 이 경우).

  - **운영점(부모 PROD-2·PROD-3, 키 top1_or_overlap τ 0.2, 후보 5).** 기본 τ 0.5는 측정한 τ 0.2와 적중이 0.1%p 안에서 같다(PROD-2 격자).

    - "엄격 거짓 적중"은 문장이 다른 질문에 캐시 결과(공개 또는 보류)를 준 것이다. 자료 안의 자연 중복(같은 질문을 다르게 쓴 두 요청)을 포함한다. 바이트까지 같은 문장(자료 중복)은 따로 셌다.
    - Jev 재질문 변동은 같은 쌍을 다시 물을 때 θ를 건너는 비율(EVID-8 재질문 표본)로 추정한 적중↔미적중 변동이다. 미적중은 평소 경로로 가므로 오답이 아니다.
  - **효과.** 적중 1건이 작성기 호출을 평균 2.3회 아낀다. 적중 경로 요청 시간의 중앙값은 약 1초다(검색 임베딩 제외, 같은 요청의 신선 기록 6~25초). 미적중은 조회 판정만큼(중앙값 0.1~0.5초) 늘어난다.
  - **측정 범위.** 13 KB(6개 언어)이고, 캐시는 EVID-7 r1 한 번의 결정(12,972항목)에서 만들었다. 같은 질문을 여러 번 기록할 때의 저장 규칙, 적재 뒤 KB가 바뀌는 경우의 실측, 미적중의 라이브 작성기 비용은 재지 않았다.

## 9. 이 문서가 말하지 않는 것

- **모델 조합이 바뀐 경우.** 다른 작성기·판정기·임베딩에서는 §2·§3이 성립한다는 근거가 없다.
- **새 holdout.** 실제 개정 fresh 200과 정적 KB는 여러 실험에서 이미 쓴 자료다. 새 holdout이 아니다.
- **한 번만 모은 live.** 측정 대부분은 비교군마다 한 번 모은 값이다. 작성기 재표본만으로도 정적 gold 정답이 몇 건씩 달라진다(U30 CTL24, PERF-1).
- **스트레스 부하.** U32 ACL churn live(472요청)에서는 두 arm 모두 마감 초과 ERROR가 약 33%였고, 원인을 아직 확인하지 않았다. 동시 쓰기가 계속되는 부하의 가용성은 이 문서의 수치로 약속하지 않는다.
- **정확성·보안·로컬 실행의 인증.** RVG는 연구 저장소에서 동작을 보존해 분리한 runtime이다.
