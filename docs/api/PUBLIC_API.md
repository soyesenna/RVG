# RVG public runtime API (`rvg-runtime-api/0.1`)

The public path for external applications, research runners and benchmark submission adapters. Every name is a public name of `import rvg` (`rvg.__all__`). Do not call internal modules (`rvg.control`, `rvg.temporal.gate`, `rvg.storage.*` and so on) directly. A machine-readable mapping goes out with every release as `rvg_public_api_map.json` in the hand-off directory (format: `api_mapping` of KB-FF `kbff-rvg-handoff/1.0`). That file is made by `scripts/make_api_map.py`.

The Korean original is [PUBLIC_API.ko.md](PUBLIC_API.ko.md). This English text is canonical; both carry the same numbers (`scripts/check_doc_numbers.py`).

**This API only assembles existing objects and delegates to them.** `answer` calls `UniversalEngine.answer` once and does not change its result. There is no retrieval, rewriting, re-verification, status upgrade or fallback to another provider. The output JSON schemas are `rvg/resources/schemas/api/*.schema.json`.

## Lifetime and configuration

```python
import rvg

async with rvg.open_session(storage, settings, root=..., environ=..., transport=..., providers=...) as session:
    ...
```

- `rvg.open_session(storage, settings=None, *, root=None, environ=None, transport=None, providers=None, max_documents=24)` builds a session **synchronously**; use it as an **async context manager**.
  - `storage`: an open `rvg.Storage`/`rvg.TemporalStore` (owned by the caller; the session does not close it), or a storage configuration (a `storage.json` path, a dict or an `rvg.StorageConfig`). Given a configuration, the session opens it with `rvg.open_storage` and closes it.
  - `settings`: `rvg.Settings`. The intended use is that the caller builds `rvg.Settings(...)` from its own configuration (it reads only arguments and environment variables, not `.env` files) and passes it in. Arguments are only field names or the alias (`rvg_mode`), case-insensitive. Any other name is `ConfigurationError(CONFIG_UNKNOWN_SETTING)` (0.1.0; before, it was silently ignored, so `Settings(rvg_mode="live")` stayed mock). Unrelated names in the environment or in `.env` are ignored. If `settings` is left out: `rvg.load_settings(root or the CWD)`, a convenience for standalone use that reads the `.env` of that location. Providers: if `providers` (a dict of caller-built objects: `decision`, `writer`, `extractor`, `embedding`) is given, it is used as is. Otherwise they are built by the product factories (`decision_provider` and the others) on `transport`. Without `transport` either, the session creates and owns an `httpx.AsyncClient(trust_env=False)`.
  - A storage configuration points to DSNs only by **environment variable name** (`dsn_env`, `url_env`). Values can be passed with `environ`.
- `handoff_packet=False` (dev56, opt-in, a keyword of `open_session` and `RuntimeSession`): when on, the session attaches `result.handoff` to every answer it does not release (**Handoff packet** below). Off by default; it does not enter the settings or policy hashes.
- `await session.aclose()`: closes only the storage and the HTTP client the session opened. It may be called more than once; later operations are `OperationError(NOT_READY, session_closed)`.
- Request context: `rvg.RequestContext(tenant, principal=None, request_id=None, selected_document_ids=None, call=None)`.
  - `principal` accepts only an `rvg.TrustedPrincipal(principal_id, groups=())` **object** built by the authentication layer. A string is `FORBIDDEN_INPUT`. With `None`, only documents without ACL entries are visible.
  - `selected_document_ids` are the documents the real user selected; they **only narrow the retrieval candidates** (the existing `allowed_ids`). They are not interpreted as context for the scope of the question.
  - `call` is the request budget and deadline (`rvg.CallContext`); the default is `session.new_call(deadline_seconds=None)` (= `Settings.context()`).

## Operations

| Neutral operation | Public path | Mode | Input | Output (schema) | Errors |
|---|---|---|---|---|---|
| capabilities | `rvg.capabilities()` / `RuntimeSession.capabilities()` | sync | none / session | static table (+ `session` configuration). Every entry has `status`, `evidence`, `implemented`, `evidence_level`, `scope`, `default`, `experimental` | none (opens no connection) |
| describe_runtime | `RuntimeSession.describe_runtime()` | sync | session | `runtime_description` | none |
| ingest | `RuntimeSession.ingest(documents, context, *, prepare_vectors=True)` | async | a list of `TemporalDocument`, dict or `IngestItem(document, access)` | `ingest_result` | per-document `REJECTED`/`ERROR` rows; context errors are `OperationError` |
| apply_event | `RuntimeSession.apply_event(event, context, *, prepare_vectors=True)` | async | `RevisionEvent`, `RevokeEvent`, `AccessEvent` or a dict (`type`: revision/revoke/access) | `event_result` | `OperationError` (`INVALID_INPUT`, `FORBIDDEN_INPUT`, `UNSUPPORTED_CAPABILITY`) |
| answer | `RuntimeSession.answer(request, context)` | async | `TemporalQuestion` or a dict (`text`, `as_of`, `known_at`, `locale`) | `answer_envelope` (`result` is the engine dict as is) | a failure inside the engine is `result.status = ERROR`; input and configuration errors are `OperationError` |
| health | `RuntimeSession.health(level="liveness", context=None)` | async | `liveness` or `readiness` (needs a tenant) | `health` | `OperationError(INVALID_INPUT)` |
| export_artifact_lineage | `RuntimeSession.export_artifact_lineage(reference, context)` | async | a request_id (or `{"request_id": ...}`) | `lineage` | an unknown reference, another tenant and another principal are all `lineage_reference_unknown` |
| close | `RuntimeSession.aclose()` | async | session | none | none |
| fixed_draft_verify | none | — | — | — | **UNSUPPORTED**: no standalone public verifier operation |

`OperationError` has a `code` (`UNSUPPORTED_CAPABILITY`, `INVALID_INPUT`, `FORBIDDEN_INPUT`, `NOT_READY`, `BACKEND_ERROR`, `PROVIDER_ERROR`, `TIMEOUT`, `INTERNAL_ERROR`) and a `native_code` (the name of the rule or failure type), and serializes with `to_dict()` (schema `operation_error`). Its message never contains request or document text, secrets or DSNs.

## Semantics

**ingest.** Each item (its ACL and its revision together) is stored in **one transaction** (RVI-07A, from dev3: a failure in the middle does not change the ACL either). The result is `STORED` (a new event), `DUPLICATE` (the same bytes are already there), `REJECTED` (a rule refused it and nothing changed; e.g. `immutable_temporal_revision_changed`, `…:observation_before_publication`) or `ERROR` (backend failure, type name only). If `IngestItem.access` is given, the document's ACL is changed in the same transaction (`None`: cleared, `DocumentAccess(allow, deny)`: replaced, `DocumentAccess(allow=())`: explicit deny-all, the default `"unchanged"`: left alone). Any immutability violation is refused before writing. A backend failure is that item's `ERROR`, and the whole transaction is rolled back. With `prepare_vectors=True`, the tenant's revisions without a vector are embedded (the existing `TemporalRetriever.index`).

Readiness is reported as three separate states. Each has a `state` (READY/NOT_READY/UNKNOWN/NOT_APPLICABLE), an `observed_at` (when the session checked) and a `reason`.

- `durable_commit`: the state-store transaction finished.
- `embedding_ready`: every embedding input of the stored revisions is stored as a vector; otherwise `vectors_pending:N`.
- `index_visible`: the index view of the next query is built from the committed vectors and generation (`query_time_view:<index>`). Revisions without a vector are retrieved through the BM25 pending path (`lexical_fallback`).

The runtime does not record the commit time of the source separately. The caller measures event times.

**apply_event.** `revision` is the same as ingest. `revoke` revokes every revision of the document (`DUPLICATE` if it is already revoked). `access` replaces the whole ACL of the document in one transaction (`SQLiteState/PostgresState.replace_access`). The ACL epoch rises by 1 for every changed entry, and an outbox entry like that of `set_access` is left, so the catch-up of a deployment move replays it as is. If the ACL is already the same, nothing changes (`DUPLICATE`). An event with an `event_id` goes through the **event ID ledger** (RVI-07A, from dev3): the key is `(tenant, issuer, event_id)`, where `issuer` is the trusted `RequestContext.issuer` (otherwise the principal ID, otherwise `default`). The same key with the same content (a digest of the tenant, the issuer and every field of the event) is a `DUPLICATE` that returns the first result (`event_id_replayed`); the same key with different content is `OperationError(INVALID_INPUT, event_id_conflict)`, and the state does not change. The ledger check, the ACL, the revision or revocation, the outbox and the ledger row are one transaction. An event without `event_id` is checked, as before, only for **content** duplicates. A backend failure of a revocation or ACL event is `OperationError(BACKEND_ERROR)`. ACLs are per document_id (common to every revision), and deny wins over allow. `allow=()` is an explicit deny-all: it is stored as an allow entry that allows only a reserved name (prefix `rvg-reserved:`) no principal can have, so the storage schema is the same and earlier versions also hide the document from everyone. Principal, group and ACL names with the reserved prefix are refused. The ledger is not yet part of the PORT-3 tenant move (export/import).

**answer.** Returns the envelope `{api_version, request_id, result, usage}`. `result` is the result of `UniversalEngine.answer` as is (`status` FULL/PARTIAL/ABSTAIN/UNRESOLVED_SCOPE/ERROR, `short_answer`, `sentences`, `evidence_ids`, `release`, `snapshot`, `config_hash`, `storage`, `audit`, `trace` and more).
- **A result that is not released carries no draft value (0.1.0).** For `ABSTAIN`, `UNRESOLVED_SCOPE` and `ERROR`, `short_answer` is `null`, `text` is the empty string, `sentences`, `assessment.claims` and `assessment_before_recovery.claims` are empty lists, and `trace.consistency.partner_short_answer` is `null`. The held draft is only in the opt-in handoff packet (`result.handoff`).
- **`evidence_ids` is the writer's evidence window.** It holds every unit given to the writer, including units it did not cite. The units the released sentences cite are `sentences[].evidence_ids`.
- **`trace` is for audit.** It holds per-stage states, reasons and unit ids, cache candidates and judgement probabilities, and the scope decision record. The trace of a result that is not released has no draft text, claims or short answer. But if the second stage is `gap` (not the policy default), the queries made from the missing parts of the draft remain in `trace.queries` and `audit[].query`. Its format may change between versions and is outside the stability promise. `usage` is the request's call counts and reported cost. The question DTO refuses extra fields (`principal_id`, `expected_answer`, gold markers → `FORBIDDEN_INPUT`). The release mode is only the policy default (`scoped_dependency` since dev27, `current` before) and cannot be chosen per request (snapshot modes are not in the public API). The guarantee scope and the measured numbers are in [Guarantees and trade-offs](../GUARANTEES.md).

**Public names of opt-in tools (0.1.0).** Every tool the documents tell you to use is an `rvg` top-level name. The internal module paths keep working as aliases, but the stability promise covers only the public names.
- `rvg.CacheMode`, `rvg.DecisionCache`: the decision cache (below).
- `rvg.write_external_set(out_dir, rows, space, *, shard_rows=65536)`, `rvg.export_external_set(state, tenant, space, out_dir)`: write an external float16 vector set for `vectors.source: external_float16` (format `docs/external-vectors.md`, example `examples/storage/external_float16.py`).
- `await rvg.build_candidate_codes(storage, tenant, space, dims=None)`: builds the codes of the candidate stage (`vectors.candidate_stage: turboquant_mse4`). `space` is an `EmbeddingSpace` (the dimensions are read from it) or a space fingerprint (then `dims` is needed). On a store with the candidate stage off: `ContractError(candidate_stage_off)`.

**Command line (0.1.0).** `rvg ingest FILE.jsonl --storage storage.json [--tenant T]` reads one JSON object per line. Each line is a document (`TemporalDocument` fields), `{"document": …, "access": {"allow": […], "deny": […]}}`, or an event (`{"type": "revision" | "revoke" | "access", …}`, the same format as `apply_event`). The lines are applied in order, and then the revisions without a vector are embedded (not with `--no-vectors`). The result is the count per outcome and the refused lines (line number and reason only; the content is not printed). `rvg universal-query … --principal ID --group G` (`--group` repeatable) asks as that principal. This means trusting the caller of the command line (an operator) to choose the principal. The help text is in English.

**Handoff packet (dev56, opt-in, PROD-1).** With `handoff_packet=True` (session, `UniversalEngine`, CLI `--handoff-packet`), results that are not released (`ABSTAIN`, `UNRESOLVED_SCOPE`, `ERROR`) get `result.handoff` (schema `handoff_packet`, `handoff-v1`). It is material for the person who takes over the request.
- **It is not a release.** `kind: handoff_draft`, `released: false`. It is not attached to released results (`FULL`, `PARTIAL`; the envelope schema prevents it), and it enters neither the release record (`release`) nor the lineage. With the option on, released results and release records are byte-identical, and the model and storage calls are the same (building the packet adds only one read-only release check).
- **Contents.** For every stage (`stage1`, `stage1_top1`, `stage2`, `partner_draft`, `conflict_rewrite`): the writer's evidence window, the draft text and citations, the writer's refusal conditions (`not_answerable`, `no_sentences`, `empty_short_answer`, `citation_outside_evidence`) and raw output, and the controller's claim→sentence mapping, labels, probabilities, signals against thresholds, states and reasons. Beyond that: the list of reason codes (`reasons`), the draft handed over (`handed_draft`: the first that exists in the order second stage → first stage → top-1 draft), the comparison of the second stage and the paired draft (`comparison`), the evidence unit texts and their validity state (`evidence`), and the automatic flags (`flags`: `claim_not_supported`, `answered_below`, carrying the note `"automatic flag, low confidence"` — the flag precision read in PROD-1 (b) is 14.5% [10.3, 20.1], hence the low confidence). The premise check is not in the policy, so `premise: not_checked`.
- **Withholding.** Only the units the asker can see at the moment the packet is built carry their text: the document passed the release check (not revoked, the ACL allows), is not on the exclusion list, is inside the selection if there is one, and the validity gate saw the unit as ELIGIBLE. Otherwise only `{id, gate, withheld}`. If even one unit a stage's writer saw is withheld, everything that stage wrote (draft, claims, raw output, short answer) is withheld. If the release check cannot be read, every unit is withheld.

**Decision cache (code dev57, adopted opt-in by the user's decision in dev58; PROD-2 and PROD-3 are REJECT — grounds and operating points in `docs/GUARANTEES.md` §6).** Turned on with `decision_cache=rvg.CacheMode(rvg.DecisionCache(path), …)` (session, `UniversalEngine`) (public names since 0.1.0; the internal path `rvg.universal.cache` also works). It loads finished decisions (released and held) into a local store (`record`) and reuses them for a new question whose evidence window shares the top-1 document or overlaps (`match`, τ default 0.5) and that Jev calls the same question (`lookup`, θ default 0.9). Both are on by default (`record=True`, `lookup=True`; the `record` default changed to True in 0.1.0). For a lookup-only cache pass `record=False`; to only fill one, `lookup=False`.
- **The writer is not called.** A released entry is judged again by the controller with the new question on the current evidence window and then passes the release check (if the window differs, the claims are judged again too). If that fails, the usual path runs. A held entry returns the same hold only for the same window.
- **Equivalence judgement.** The probability of one Jev boolean question (prompt `universal.cache.EQUIVALENCE`, the same wording as variant A of the EVID-8 Jev equivalence judgement). A candidate that is the same sentence after normalisation is used without a judgement (p = 1).
- **Not reused.** An entry whose cited unit is outside the current evidence window (the retrieval result after the current validity, permission, exclusion list and selection) — for example an entry released from the scope_top1 top-1 draft — and entries of another policy hash, arm or tenant.
- **Short answer.** The short answer of a cached release is the short answer of the original release (including releases whose sentences recovery rewrote).
- **Records.** A release from the cache leaves `release.source.cache = {entry, p, theta, match}`, which also reaches the lineage. The trace `cache` keeps the candidates and the judgement probabilities. Equivalence judgements and re-check calls go into the tape and replay.

**health.** `liveness` looks only at the session state, the policy resource hash, the prompt manifest check and the provider configuration: no DB, network or model calls. `readiness` reads the generation of the already open state store with a 5 s limit. For a vector service it also reads a read-only count and the projection frontier (`DEGRADED space_not_projected_yet` if there is no projection yet, `DEGRADED projection_frontier_behind` if the frontier lags; queries continue through the exact overlay). No schema creation, migration, matrix warmup or provider call. Errors carry only the exception **type name**. `provider_calls: 0` and `state_mutated: false` are a self-report by design; the caller has to measure separately. `unverified` lists the components that were not checked (e.g. provider reachability).

**Validity and permission (RVI-02, 02b, from dev4, dev5).** Retrieval returns only documents the principal can see, that are not revoked and that the user selected (the content plane). The validity gate looks for **higher revisions (R-REV-1) and `supersedes` declarations (R-REV-2) that target those documents, across the tenant's whole authoritative store** — including revisions that are not visible, are revoked, were not selected or were not retrieved (the validity plane). Only those revisions' metadata (target, unit, family, publication, observation and validity times, authority) is used by the code rules. Their text goes to neither the writer, the judge nor the user, and the gate's reason does not name the document either (`explicit_replacement:withheld`). A declaration before its validity starts, or observed after `known_at`, is not applied yet, and a declaring document that is revoked or replaced does not bring the old value back. An explicit replacement applies even when the two documents' families differ (RVI-02b, KB-FF R-REV-2). A declaration whose order (the declaring document published later) or authority (primary replaces only primary) does not fit is not guessed at; it is unresolved (held). As a result, a question with a hidden revision is held instead of answered with the old value; the differences in status, reason and the tenant's knowledge number remain as a signal of existence. A hidden revision written only in text (no structured `supersedes`) is not detected.

**export_artifact_lineage.** Records only the **released cited units** of the answers this session gave: the `sentences[].evidence_ids` of the released sentences, not the writer's evidence window (`result.evidence_ids`) (fixed in 0.1.0; before, uncited window units were recorded too). By default 1,024 are kept in memory, and they disappear when the session ends. On export, the **current** ACL and revocations are applied again. Each unit goes out as an `evidence_unit` (document, revision, unit, source sha256, span, unit sha256) and a `vector` (the input hash of the embedding input the unit is in — the whole revision or a K8 piece —, the space, `PRESENT/ABSENT`, `derived_from`). Hidden or revoked sources drop out with no ID, title or hash, leaving only `completeness=PARTIAL` and `missing_reasons=["ACCESS_RESTRICTED_OR_REVOKED"]`. An answer that was not released (ABSTAIN/ERROR) has no citations (`notes: ["no_released_evidence"]`). A hash identifies bytes; it is not a proof that a sentence is supported. Derived graphs and summaries are not in this runtime. There is no operator audit export.

## Versions

The library version (`rvg.__version__`), the API contract (`rvg.API_VERSION` = `rvg-runtime-api/0.1`), the observation contract (`rvg.OBSERVATION_VERSION` = `rvg-observation/0.1`), the policy hash (`rvg.policy_hash()`) and the prompt manifest hash (`describe_runtime()["prompt_manifest_sha256"]`) are different values. An added field is a minor change; a change of meaning is a new contract version.
